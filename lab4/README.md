## 1. Мета роботи
Набуття навичок проведення Code Review, ідентифікації "запахів коду" (code smells) та застосування рефакторингу для покращення якості ПЗ без зміни його зовнішньої поведінки.

---

## 2. Результати Code Review
Під час аналізу модуля `renderpen.py` було виявлено наступні проблеми:

| № | Проблема | Категорія | Рекомендація |
| :--- | :--- | :--- | :--- |
| 1 | Числа 50.0 та 1000.0 вжиті без пояснень | Magic Numbers | Винести у константи класу |
| 2 | Метод `validate_label` занадто складний (оцінка B) | Excessive Complexity | Спростити логіку через функцію `all()` |
| 3 | Метод `validate_upload` робить забагато дій | SRP Violation | Розбити на приватні методи перевірки |
| 4 | Відсутня типізація параметрів | Style / Tooling | Додати Type Hints для стабільності |
| 5 | Закоментований код або неінформативні докстрінги | Dead Code / Naming | Оновити документацію та видалити зайве |

**Посилання на Pull Request:** [ВСТАВ СВОЄ ПОСИЛАННЯ ТУТ]

## 3. Результати рефакторингу
Виконано наступні операції:

1. **Replace Magic Number with Constant:** Всі ліміти розмірів та координат винесені в константи (напр. `MAX_FILE_SIZE_MB`).
2. **Extract Method:** Валідація розширення та розміру винесена в окремі методи `_check_extension` та `_check_positive_size`.
3. **Simplify Conditional:** Логіку перевірки координат спрощено, що дозволило знизити цикломатичну складність.

## 5. Підсумкова рефлексія
Під час роботи я переконалася, що рефакторинг — це не просто "прибирання", а критична частина розробки. Найціннішим досвідом було використання інструменту Radon для об'єктивної оцінки складності коду. Тепер код RenderPen став набагато легшим для читання та супроводу.
